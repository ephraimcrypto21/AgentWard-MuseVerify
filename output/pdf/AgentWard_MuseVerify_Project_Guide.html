01 / PROJECT GUIDE

Problem and core value

Candidate alerts need evidence before repair. Coding agents need containment when they inspect untrusted source or propose changes.

Two problems, one controlled workflow

Automated findings can consume maintainer time without proving a reachable bug. A model-generated patch can also change behavior or introduce a new weakness. Meanwhile, comments and literals can carry indirect instructions aimed at credential access, destructive actions or fabricated audit results.

AreaCurrent stage
AgentWardSource-aware ingress, proposed-tool-action policy, additive operator restrictions and checkpoint rewind. It protects the controlled workflow.
MuseVerifyIsolated exploit reproduction, Meta-led repair, independent review, CodeShield, AST tripwires, self-play and functional regression.
Core ruleModel advice can propose a repair. Only the orchestrator can accept it after all required evidence gates pass. Model judgments cannot waive deterministic controls.
EvidenceProtected Docker traces and artifact hashes identify tested behavior. Static findings, fixture modes and live verified repairs stay distinct.

02 / PROJECT GUIDE

Architecture and trust boundaries

The workstation coordinates policy and verification. Submitted source and model output remain untrusted throughout the workflow.

What must be trusted

The operator configuration, application services, selected provider identities, Docker host and kernel, runtime image, bootstrap and tracer form the trusted base. A compromised host or service can undermine the evidence it produces.

What evidence establishes

Authentication controls who can request work. Hashes bind results to particular source and harness artifacts. Protected kernel traces record selected execution behavior. The orchestrator combines that evidence with positive controls, reviews and regression results.

Two different contracts

Classifier contract v2 binds model, policy, language and source hashes. Sandbox protocol v3 binds protected runtime evidence, artifact hashes, language, runtime and filename. Both must match the workstation.

03 / PROJECT GUIDE

The seven-phase workflow

Every supported language uses the same orchestrator. A failed or unavailable required gate prevents a verified repair.

PhaseWork performedAcceptance evidence
1 / Ingress ShieldClassify complete source and sanitize injected instructions.Full coverage, rescan after changes, exact model/policy contract and source hashes.
2 / Syscall SandboxReproduce supported exploits with deterministic probes in Docker.Protected strace evidence, artifact identity and completed behavioral probes.
3 / Runtime HooksApply screening, ensemble policy checks and trajectory monitoring.Valid unanimous votes and the current operator policy revision; violations trigger rewind.
4 / Patch VerificationSynthesize a repair; inspect contracts, static paths, reviews, CodeShield and tripwires.All applicable structural, scanner and independent-review gates pass.
4.5 / Adversarial Self-PlayReplay bounded mutated and multi-step scenarios.Original-code positive controls succeed; no surviving exploit in the candidate; valid evidence.
5 / RegressionReplay exploits, normal inputs and decoy probes.Normal result preserved; exploit blocked; decoy triggers the logger, normal probe does not.
5.1 / Semantic HunterInspect related modules and semantic paths with Wonder-led analysis.Static findings and unresolved assumptions remain visible, separate from runtime proof.

Concurrency and reporting

Phase 2 overlaps with graph construction and the initial policy baseline. The pipeline runs at most three containers concurrently. Passing that baseline cannot replace the later sandbox, patch or regression evidence.

A valid Phase 2 BENIGN result still requires Phase 3 policy review before FALSE_POSITIVE. For Node, static findings outside SQL/command probe coverage remain INCONCLUSIVE. Benign controls skip patch synthesis and later repair stages.

04 / PROJECT GUIDE

Supported languages and targets

Language support means a defined parser, execution harness and verification contract. It does not imply arbitrary project builds.

LanguageFilesSupported verification scope
Python.pyExisting Python parsing, graph analysis and benchmark probes.
JavaScript.js / .mjs / .cjsSingle-file Node ES/CommonJS modules with compatible exported SQL/command functions.
TypeScript.ts / .mts / .ctsThe same Node probes with erasable syntax. Original source executes in Node 24; scanning uses AST-based type erasure.

Node target contract

Node targets support named top-level functions and arrow functions in ES/CommonJS exports. All exports (maximum eight) must accept a single scalar SQL/command probe argument and return serializable results. Ambiguous or partial probe coverage is rejected.

Execution uses built-in dependencies such as node:sqlite and node:child_process. Every export must return successfully for agentward_normal; other business contracts need additional probes. Node always runs in Docker.

TypeScript behavior

Tree-sitter parses without execution. Type-only nodes are erased and reparsed as JavaScript for CodeShield. Original TypeScript executes in Docker. Supported syntax includes annotations, interfaces, type aliases, generics and as-assertions; there is no type checking.

ResultMeaning
UNSUPPORTED_LANGUAGEExtension outside the registry: for example Go, Java, Rust, JSX or TSX.
INVALID_SOURCESyntax is invalid for the selected language.
UNSUPPORTED_TARGETThe supported language has no fully compatible Node probe surface.
Outside the current target contract

Browser apps, npm dependencies, multi-file execution, constructed classes and project compiler plugins are unsupported. TypeScript enums, namespaces, decorators and unsupported transformations cannot pass the complete chain.

05 / PROJECT GUIDE

Ingress: detection with context

The ingress guard detects instructions aimed at manipulating the audit. It is a separate task from finding vulnerabilities in the program.

How the current guard works

The Horizon-Labs/prompt-injection-guard-small model, pinned at revision 5ed691c under Apache-2.0, receives bounded parser facts followed by the complete source. The prefix describes language, declared names and syntax-node kinds; it never declares the source safe. Valid syntax and filenames cannot bypass classification.

ControlCurrent behavior
Coverage512-token windows with 128-token overlap; the highest injection score controls the decision. Risk threshold: 0.40.
Work boundAt most 256 windows per original or sanitized input. Over-limit or incomplete coverage is denied, without silently truncating source.
SanitizationRecognizes explicit role-directed bypass or fabricated-audit instructions in comments/literals, including decoded base64. Modified source receives a full rescan.
Model integrityFive artifacts are pinned and SHA-256 verified. Safetensors, no remote code, no inference-time downloads; provisioning is explicit.
EvidenceContract v2 binds the model revision and policy identity, language and original/sanitized hashes. Stale or mismatched responses cannot authorize a live run.
What “detection remains probabilistic” means

The model assigns a learned risk score. It can occasionally flag harmless code or miss an unfamiliar instruction attack. 78 of 78 regression cases passed means those specific cases behaved as expected; it does not mean every future input will be classified correctly.

The 0.40 threshold is a decision setting, not a measured 40% chance that a program is unsafe. Ingress ALLOW means the file can proceed to the next checks; a vulnerable SQL or command function may correctly pass ingress and then fail sandbox verification.

Short HTTP 429 capacity delays allow at most three identical client requests; exhausted retries remain unverified. All 13 current Node corpus files received unchanged-source ALLOW, with a maximum measured injection score of 0.017127.

06 / PROJECT GUIDE

Protected runtime evidence

The remote sandbox executes submitted code under a fixed, constrained runtime and keeps the evidence outside the payload’s control.

BoundaryEnforced control
IdentityBearer authentication and bounded request schemas. Protocol v3 binds source/harness SHA-256, language, runtime and target filename.
PrivilegesTrusted root tracer and immutable bootstrap start first. Payload UID/GID: 65534; supplementary groups cleared; effective/permitted capabilities empty.
Filesystem / networkNo container network. Read-only root, source inputs and bootstrap; bounded 64 MiB workspace and 16 MiB temporary storage.
Trace protectionRoot-owned kernel trace in a POSIX-ACL-protected directory. Payloads cannot read, overwrite, unlink or replace host-backed evidence.
Resources256 MiB memory/swap ceilings, CPU/PID limits and bounds on time, output, trace bytes and event counts. Overflow and timeout deny evidence and trigger cleanup.
Runtime choiceFixed python3/node allowlist. Python isolated startup; Node loader environment variables cleared. No arbitrary caller-selected interpreter.

Conditions for accepted execution evidence

The client requires matching protocol and artifact identity plus complete protected traces and valid behavioral results. Missing traces, tampering, truncation, abnormal completion and unsupported ownership/ACL setup deny evidence. Docker failure cannot trigger production host execution.

Deployment requirements

The supported node uses rootful Linux Docker without user-namespace remapping and an ACL-capable temporary filesystem. Rootless or remapped configurations are not validated.

Evidence is authenticated and hash-bound, not digitally signed. Selected syscalls and payload-produced probe lines cannot prove all possible behavior; the other acceptance gates remain necessary.

07 / PROJECT GUIDE

Runtime policy and workspace rewind

Phase 3 reviews the controlled tool workflow using the completed ingress and original sandbox evidence.

Screen actions before authorizing continuation

agentward_stage3.py checks proposed action text for destructive commands, secret-exfiltration patterns and high-entropy strings, and tracks an estimated token budget. Known credential values are redacted from action text. Meta Spark leads concurrent policy and trajectory reviews with the selected independent auditors.

MechanismScope
Tool hookenforce_permissions.py evaluates command-bearing JSON arguments for a PreToolUse integration. These are application hooks, not kernel syscall interception.
Policy baselineA checklist may be prepared during Phase 2. Final Phase 3 authorization requires the observed Docker evidence; preparation is not permission.
Checkpoint / rewindThe guard copies top-level workspace files and writes SHA-256 manifest entries. trigger_rewind restores copies and removes new top-level files.
Trajectory monitorDrift, forbidden actions, missing review or stale policy can deny continuation. Detected violations can halt the session and trigger rewind.

Add operator restrictions during a run

POST /api/steer
{"constraint":"Forbid subprocess calls"}

Restrictions are additive and shared across dashboard batch workers. Each revision invalidates older in-flight approval. Recognized rules also have AST checks; broader natural-language rules depend on model review.

What rewind does not promise

The checkpoint covers the disposable workspace, not arbitrary host effects, nested files or Git history. strace observes submitted code inside Docker. The tool hook must be integrated to mediate another agent’s actions.

08 / PROJECT GUIDE

How a repair earns acceptance

A proposed patch stays a candidate until independent checks agree with the observed behavior.

Preserve the public contract

Patch checks preserve relevant function interfaces and sync/async behavior. Node checks also compare exported parameters and type signatures. Model-generated text cannot waive structural rules, scanning or current operator restrictions.

Use independent evidence at each step

GateWhat it contributes
Policy and reviewValid votes from the selected reviewers, bound to current additive operator constraints. Missing or malformed reviewer output denies approval.
Static checks and CodeShieldContract inspection, call/taint findings and scanner results. TypeScript is erased and reparsed for JavaScript rules; execution uses the original source.
Structural tripwireA reachable AST decoy equality guard calls a logger such as _tripwire(). A comment mentioning a canary cannot satisfy this check.
Adversarial replayDeterministic mutations and bounded scenarios run against original and candidate code. Original-code positive controls must reproduce the relevant behavior.
RegressionThe original exploit is blocked, tested normal results are preserved, and the tripwire fires only for decoy probes.

Bounded self-play

Node tests three deterministic scenarios: syntax mutation, stored-value replay and URL-encoding replay. All three must be neutralized with valid evidence and successful original-code controls. Python also supports bounded model-proposed scenarios executed by deterministic harnesses.

Zero surviving mutations alone is insufficient. Unsupported or unproven scenarios are not counted as neutralized. Storage adapters test replay robustness, not arbitrary native persistence.

Review the exact diff before integration

Accepted files and diffs go to patches/<run-id>/. Run git apply --check against the unchanged source before applying a diff; this is an integration step, not an automatic pipeline gate. Corpus acceptance applied all eight diffs in temporary directories and matched the saved patch hashes.

Providers and operator control

Meta remains mandatory for every live run. Optional providers add independent review when they pass pre-flight.

muse-spark-1.3 leads runtime policy and patch synthesis. muse-wonder-1.0 leads deeper semantic analysis. In Meta-only operation, the two native models cross-check each other.

ModeSelected participants
autoMeta primary plus every healthy secondary.
all_threeMeta, Anti-Gravity and Custom; notices identify unavailable secondary providers.
meta_plus_agyMeta plus verified Anti-Gravity.
meta_plus_customMeta plus verified Custom BYOK.
meta_onlySpark and Wonder cross-check each other.

When no requested secondary passes pre-flight, Meta’s other native model supplies the independent review. If Meta is offline, a live run cannot proceed. A selected reviewer that later fails cannot silently become an approval.

Pre-flight and configuration

Provider discovery runs concurrently and caches dashboard status for 60 seconds. A forced refresh reloads .env. Each run retains its successful discovery snapshot while configuration is unchanged; task failures still deny approval. Configure META_API_KEY, ENSEMBLE_MODE and optional Anti-Gravity or Custom endpoint/model credentials locally.

Optional high-end co-auditors

Anti-Gravity tries a supported selected model, then a deduplicated cascade: gemini-4-argon, claude-opus-5-5, claude-sonnet-5.5 and gemini-3.8. Quota failures are recorded during pre-flight. Custom BYOK supports compatible Responses and Chat Completions endpoints, including a /v1 base.

Requested topology versus verified participation

all_three requests all three providers but excludes an unhealthy secondary with an explicit notice. It does not waive the required independent review. A selected reviewer failure cannot silently become approval.

Install Tailscale on both hosts, join the same tailnet and run on the node:

tailscale ip -4
sudo tailscale serve --bg --tcp=8000 tcp://127.0.0.1:8000
sudo tailscale serve --bg --tcp=8001 tcp://127.0.0.1:8001

Preserve the private transport boundary

Tailscale carries HTTP inside its encrypted network. Restrict tailnet access and retain node bearer authentication; Serve is not public Funnel exposure. For a same-host setup use 127.0.0.1:8000/8001. Restart the dashboard after endpoint changes.

18 / PROJECT GUIDE

Interpreting results and limits

Use each outcome as evidence for the behavior and coverage actually checked. A completed run is not a formal proof of program safety.

Result or signalInterpretation
Ingress ALLOW / SANITIZEDThe source may continue to the remaining gates. This is not a vulnerability verdict.
Ingress BLOCKED / UNVERIFIEDA classified attack was denied, or required evidence was absent/stale. The pipeline records an ingress-blocked outcome when live ingress cannot pass.
REMEDIATEDApplicable gates and tested repair behavior passed with production evidence. Review the diff and stated assumptions before integrating it.
FALSE_POSITIVESafe-path evidence and Phase 3 policy passed; patch synthesis was skipped. Node also requires no static finding outside its probe CWEs. This differs from an ingress classifier false positive.
SIMULATED_*Fixture-based demonstration. It cannot establish a production repair or export a verified SARIF fix.
INCONCLUSIVE / rejected / failedEvidence, policy, repair or regression requirements were not satisfied. Missing evidence is never an implicit pass.

Coverage that remains bounded

Detection: unfamiliar instructions can evade the learned model; benign code can still be misclassified. New regressions should expand the corpus and trigger review of the pinned policy and model.

Program analysis: Python propagation is bounded; Node taint analysis is intraprocedural. Reflection, closures, dynamic dispatch, external libraries and Node cross-file flows need additional review. CodeShield coverage is narrower than a complete security audit.

Runtime and operations: selected probes and syscall traces cover observed behavior. The kernel, daemon, service, tracer and operator remain trusted. The shared token identifies an authorized workstation, not an individual user; provider data handling remains an operator decision.

A useful next validation step

For a new production target, add representative functional probes and run the full live pipeline with fresh provider pre-flight. Expand adapters explicitly for new languages, application shapes and vulnerability families. These are extension directions, not shipped capabilities.
